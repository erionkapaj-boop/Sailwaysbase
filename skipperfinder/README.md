# SkipperFinder

Δημόσια αγορά ναύλων ευκαιρίας για ιστιοπλοϊκά. Το βασικό σενάριο: μια
ναυλομεσιτική εταιρεία έχει ένα σκάφος που πρέπει να μεταφερθεί σε άλλη
μαρίνα (repositioning) και, αντί να πληρώσει κάποιον για τη μεταφορά, το
νοικιάζει πάρα πολύ φθηνά σε κάποιον που θέλει να κάνει το ταξίδι μέσα σε
συγκεκριμένο διάστημα. Πελάτες μπαίνουν στη σελίδα χωρίς να στοχεύουν
συγκεκριμένο προορισμό — απλά βλέπουν όποιες ευκαιρίες υπάρχουν αυτή τη
στιγμή.

Είναι **αυτόνομο, ανεξάρτητο** project μέσα στο ίδιο repository (δικό του
`package.json` και stack, χωρίς κοινό κώδικα με τη ρίζα του repo ή με το
`skipper-app/`) — το ίδιο μοτίβο που ακολουθεί ήδη το `skipper-app/`. Είναι
επίσης η υλοποίηση του "SkipperFinder" που αναφέρεται ως μελλοντική σύνδεση
στο README του Skipper App (§ Ετοιμότητα για μελλοντική σύνδεση) — καμία
τέτοια σύνδεση δεν είναι ενεργή ακόμα, αλλά το naming είναι σκόπιμα το ίδιο.

## Stack

- React (Vite) + Tailwind CSS
- Supabase (Postgres + Storage) — χωρίς login: η καταχώρηση διαχειρίζεται
  μέσω ενός προσωπικού συνδέσμου με token, όχι λογαριασμού χρήστη

## Ανάπτυξη

```bash
cd skipperfinder
npm install
cp .env.example .env.local   # συμπλήρωσε VITE_SUPABASE_URL / VITE_SUPABASE_ANON_KEY
npm run dev
```

## Βάση δεδομένων

Τρέξε το [`supabase/schema.sql`](./supabase/schema.sql) στο SQL editor του
Supabase project σου. Δημιουργεί:

- τον πίνακα `deals` (χωρίς καμία RLS policy access σε anon/authenticated —
  προσβάσιμος μόνο μέσω των παρακάτω)
- το view `public_deals`, που εκθέτει μόνο τις ενεργές καταχωρήσεις **χωρίς**
  τη στήλη `edit_token`
- τις functions `create_deal`, `get_deal_for_edit`, `update_deal`,
  `delete_deal` (`SECURITY DEFINER`, grant σε `anon`), που είναι ο μόνος
  τρόπος εγγραφής — ελέγχουν το `edit_token` πριν επιτρέψουν αλλαγή

Χρειάζεται επίσης ένα **public** storage bucket με όνομα `deal-photos`
(Supabase dashboard → Storage → New bucket) για τις φωτογραφίες σκαφών.

## Πώς λειτουργεί η διαχείριση καταχωρήσεων χωρίς λογαριασμό

Όταν μια εταιρεία υποβάλει το `/post` form, το `create_deal` RPC επιστρέφει
ένα μοναδικό `edit_token` που εμφανίζεται **μία φορά** στη σελίδα
επιβεβαίωσης (`/posted/:id?token=...`) ως προσωπικός σύνδεσμος διαχείρισης
(`/manage/:id?token=...`). Όποιος έχει αυτόν τον σύνδεσμο μπορεί να
επεξεργαστεί ή να αποσύρει την καταχώρηση· κανείς άλλος δεν μπορεί, αφού το
token δεν εκτίθεται ποτέ μέσω του public view.

## Ρόλη σε σχέση με τα άλλα δύο projects του repo

- Η ρίζα του repo (`app/`) είναι το εσωτερικό εργαλείο διαχείρισης εργασιών
  της βάσης Αλίμου — άσχετο προϊόν.
- Το `skipper-app/` είναι το επαγγελματικό εργαλείο του κάθε skipper/εταιρείας
  (επαφές, ημερολόγιο διαθεσιμότητας, ναυλώσεις).
- Το `skipperfinder/` (εδώ) είναι η δημόσια βιτρίνα ευκαιριών για τελικούς
  πελάτες. Μελλοντικά θα μπορούσε να τραβάει καταχωρήσεις αυτόματα από τα
  κενά διαστήματα του ημερολογίου του Skipper App αντί να απαιτεί χειροκίνητη
  καταχώρηση — αυτή η σύνδεση είναι σκόπιμα εκτός scope προς το παρόν.
