# SailForAll

Δημόσια αγορά ναύλων ευκαιρίας για ιστιοπλοϊκά — η ιδέα ότι το ιστιοπλοϊκό
γίνεται προσβάσιμο για όλους. Βασικό σενάριο: μια ναυλομεσιτική εταιρεία έχει
ένα σκάφος που πρέπει να μεταφερθεί σε άλλη μαρίνα (repositioning) και, αντί
να πληρώσει κάποιον για τη μεταφορά, το νοικιάζει πάρα πολύ φθηνά σε κάποιον
που θέλει να κάνει το ταξίδι μέσα σε συγκεκριμένο διάστημα. Πελάτες μπαίνουν
στη σελίδα χωρίς να στοχεύουν συγκεκριμένο προορισμό — απλά βλέπουν όποιες
ευκαιρίες υπάρχουν αυτή τη στιγμή.

Είναι **αυτόνομο, ανεξάρτητο** project μέσα στο ίδιο repository (δικό του
`package.json` και stack, χωρίς κοινό κώδικα με τη ρίζα του repo ή με το
`skipper-app/`) — το ίδιο μοτίβο που ακολουθεί ήδη το `skipper-app/`.

> **Σημείωση ονομασίας:** Το `skipper-app/README.md` αναφέρει μια μελλοντική
> σύνδεση με "SkipperFinder" — αυτό είναι ένα **διαφορετικό, ήδη υπαρκτό**
> application (εύρεση πληρώματος/skipper/hostess για ενοικιαστές σκαφών) και
> δεν έχει καμία σχέση με αυτό το project. Το `SailForAll` συνδέει τον πελάτη
> με τη ναύλωση σκάφους (ευκαιρίες/deals), όχι με πλήρωμα. Τα δύο projects θα
> μπορούσαν αργότερα να συνδεθούν σαν κόμβοι στο ίδιο δίκτυο εφαρμογών (π.χ.
> ένας πελάτης που βρίσκει εδώ μια ευκαιρία να παραπέμπεται στο SkipperFinder
> για να βρει πλήρωμα) — καμία τέτοια σύνδεση δεν υπάρχει ακόμα.

## Stack

- React (Vite) + Tailwind CSS
- Supabase (Postgres + Storage) — χωρίς login: η καταχώρηση διαχειρίζεται
  μέσω ενός προσωπικού συνδέσμου με token, όχι λογαριασμού χρήστη

## Ανάπτυξη

```bash
cd sailforall
npm install
cp .env.example .env.local   # συμπλήρωσε VITE_SUPABASE_URL / VITE_SUPABASE_ANON_KEY
npm run dev
```

## Βάση δεδομένων

Τρέξε το [`supabase/schema.sql`](./supabase/schema.sql) στο SQL editor του
Supabase project σου. Δημιουργεί:

- τον πίνακα `deals` (χωρίς καμία RLS policy access σε anon/authenticated —
  προσβάσιμος μόνο μέσω των παρακάτω)
- το view `public_deals`, που εκθέτει μόνο τις ενεργές καταχωρήσεις **χωρίς**
  τη στήλη `edit_token`
- τις functions `create_deal`, `get_deal_for_edit`, `update_deal`,
  `delete_deal` (`SECURITY DEFINER`, grant σε `anon`), που είναι ο μόνος
  τρόπος εγγραφής — ελέγχουν το `edit_token` πριν επιτρέψουν αλλαγή

Χρειάζεται επίσης ένα **public** storage bucket με όνομα `deal-photos`
(Supabase dashboard → Storage → New bucket) για τις φωτογραφίες σκαφών.

## Πώς λειτουργεί η διαχείριση καταχωρήσεων χωρίς λογαριασμό

Όταν μια εταιρεία υποβάλει το `/post` form, το `create_deal` RPC επιστρέφει
ένα μοναδικό `edit_token` που εμφανίζεται **μία φορά** στη σελίδα
επιβεβαίωσης (`/posted/:id?token=...`) ως προσωπικός σύνδεσμος διαχείρισης
(`/manage/:id?token=...`). Όποιος έχει αυτόν τον σύνδεσμο μπορεί να
επεξεργαστεί ή να αποσύρει την καταχώρηση· κανείς άλλος δεν μπορεί, αφού το
token δεν εκτίθεται ποτέ μέσω του public view.

## Κατάσταση

Πρώτη υλοποίηση (MVP σκελετός): browsing, φίλτρα, φόρμα καταχώρησης,
διαχείριση μέσω token. Πολλές αποφάσεις προϊόντος (επαλήθευση εταιρειών,
πρόληψη ψεύτικων καταχωρήσεων, αν/πώς γίνεται κράτηση-πληρωμή μέσα στο site
ή μόνο επικοινωνία, γεωγραφικό/επιχειρησιακό scope) είναι ακόμα ανοιχτές και
σκόπιμα δεν έχουν αποφασιστεί μονομερώς — βλ. συζήτηση στο repo/branch.
